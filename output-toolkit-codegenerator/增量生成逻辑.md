# 增量更新方法 `generateXmlAndIncrementalUpdate` 实现逻辑详解

## 一、方法调用链

```
用户调用API
    ↓
XmlGeneratorController.generateXmlAndIncrementalUpdate()
    ↓
1. XmlGeneratorService.generateXml()
    ↓
2. XmlGeneratorService.incrementalUpdate(xmlpath)
    ↓
IncrementalUpdateServiceImpl.incrementalUpdate(xmlConfigPath)
```

## 二、详细执行流程

### 第一步：生成XML配置文件

**方法**: `XmlGeneratorController.generateXmlAndIncrementalUpdate()`

```java
@PostMapping("/generateXmlAndIncrementalUpdate")
public ReturnT generateXmlAndIncrementalUpdate() throws Exception {
    // 1. 生成XML配置文件
    String xmlpath = xmlGeneratorService.generateXml();
    
    // 2. 执行增量更新
    String result = xmlGeneratorService.incrementalUpdate(xmlpath);
    
    return ReturnT.ok().put("data", result);
}
```

**详细说明**:

1. **调用 `generateXml()` 方法**
   - 读取配置文件中指定的SQL文件路径（`application-riskproduct.properties` 中的 `sql.absolute.path`）
   - 解析SQL文件中的所有 `CREATE TABLE` 语句
   - 为每个表提取：
     - 表名（去掉配置的前缀）
     - 字段列表及其类型
     - 表注释
   - 生成XML配置文件，保存到 `config.xml.absolute.path/xml/` 目录
   - 返回生成的XML文件路径

2. **调用 `incrementalUpdate(xmlpath)` 方法**
   - 传入刚生成的XML配置文件路径
   - 执行增量更新逻辑

### 第二步：解析XML配置并遍历表

**方法**: `IncrementalUpdateServiceImpl.incrementalUpdate(xmlConfigPath)`

```java
public String incrementalUpdate(String xmlConfigPath) throws Exception {
    // 1. 解析XML配置
    GeneratorConfig generatorConfig = XmlConfigParser.parseFromAbsolutePath(xmlConfigPath);
    
    List<TableConfig> tableConfigList = generatorConfig.getTableConfigList();
    
    // 2. 遍历每个表配置
    for (TableConfig tableConfig : tableConfigList) {
        if (!tableConfig.isGenSwitch()) {
            continue; // 跳过关闭开关的表
        }
        
        // 3. 处理单个表
        processTable(tableConfig);
    }
    
    return summary;
}
```

**详细说明**:

1. **解析XML配置**
   - 使用 `XmlConfigParser` 解析XML文件
   - 获取所有 `TableConfig` 列表
   - 每个 `TableConfig` 包含：
     - SQL建表语句
     - 包名配置
     - 后缀配置
     - 开关状态

2. **遍历处理**
   - 检查每个表的生成开关（`genSwitch`）
   - 如果开关关闭，跳过该表
   - 否则，进入单表处理流程

### 第三步：处理单个表（核心逻辑）

```
处理单个表
    ↓
1. 解析建表语句，生成ClassInfo
    ↓
2. 更新DTO文件
    ↓
3. 更新VO文件
    ↓
4. 更新Mapper.xml文件
```

#### 3.2 更新DTO文件

**方法**: `updateDtoFile(filePath, newClassInfo, tableConfig)`

```java
private boolean updateDtoFile(String filePath, ClassInfo newClassInfo, TableConfig tableConfig) {
    // 1. 检查文件是否存在
    if (!file.exists()) return false;
    
    // 2. 读取现有DTO文件
    String content = Files.readAllBytes(filePath);
    
    // 3. 解析现有字段
    List<FieldInfo> oldFields = parseDtoFields(content);
    
    // 4. 排除基类字段
    List<String> excludeFields = ["id", "createdAt", "createdBy", "updatedAt", "updatedBy"];
    oldFieldsFiltered = excludeFields(oldFields, excludeFields);
    newFieldsFiltered = excludeFields(newClassInfo.getFieldList(), excludeFields);
    
    // 5. 比对字段差异
    FieldDiff diff = FieldDiffUtil.compareFields(oldFieldsFiltered, newFieldsFiltered);
    
    // 6. 如果无变更，返回false
    if (!diff.hasChanges()) return false;
    
    // 7. 重新生成DTO文件
    String dtoContent = FreemarkerUtil.processString("riskproduct/riskproduct_dto.ftl", paramMap);
    Files.write(filePath, dtoContent);
    
    return true;
}
```

**字段比对逻辑** (`FieldDiffUtil.compareFields`):

```java
public static FieldDiff compareFields(List<FieldInfo> oldFields, List<FieldInfo> newFields) {
    FieldDiff diff = new FieldDiff();
    
    // 1. 找出新增字段（在new中有，在old中没有）
    for (FieldInfo newField : newFields) {
        if (!oldFieldMap.containsKey(newField.getFieldName())) {
            diff.addedFields.add(newField);
        } else {
            diff.remainingFields.add(newField);
        }
    }
    
    // 2. 找出删除字段（在old中有，在new中没有）
    for (FieldInfo oldField : oldFields) {
        if (!newFieldMap.containsKey(oldField.getFieldName())) {
            diff.removedFields.add(oldField);
        }
    }
    
    return diff;
}
```

**比对示例**:

原SQL:
```sql
`GRAPH_NAME` varchar(255) COMMENT '图谱名称',
`GRAPH_NUMBER` varchar(100) COMMENT '图谱编码',
`CREATOR` varchar(32) COMMENT '创建者',
`STATUS` varchar(32) COMMENT '申请状态',
```

新SQL:
```sql
`GRAPH_NAME` varchar(255) COMMENT '图谱名称',
`GRAPH_NUMBER` varchar(100) COMMENT '图谱编码',
`age` varchar(32) COMMENT '年龄',
`STATUS` varchar(32) COMMENT '申请状态',
```

比对结果:
- **新增字段**: `age`
- **删除字段**: `creator`
- **保留字段**: `graphName`, `graphNumber`, `status`

**DTO更新策略**:

原策略（已废弃）：
- 使用正则表达式删除旧字段
- 使用字符串拼接添加新字段
- **问题**: 容易破坏文件结构，产生格式错误

**当前策略（推荐）**：
- **直接使用Freemarker模板重新生成整个DTO文件**
- 优点：
  - 保证文件格式正确
  - 避免增量修改的复杂性
  - 代码更简洁可靠

#### 3.3 更新VO文件

**方法**: `updateVoFile(filePath, newClassInfo, tableConfig)`

```java
private boolean updateVoFile(String filePath, ClassInfo newClassInfo, TableConfig tableConfig) {
    // 1. 检查文件是否存在
    if (!file.exists()) return false;
    
    // 2. 直接重新生成VO文件（因为VO继承自DTO）
    Map<String, Object> paramMap = new HashMap<>();
    paramMap.put("classInfo", newClassInfo);
    paramMap.put("dtoSuffix", tableConfig.getDtoSuffix());
    paramMap.put("authorName", tableConfig.getAuthorName());
    
    String voContent = FreemarkerUtil.processString("riskproduct/riskproduct_vo.ftl", paramMap);
    Files.write(filePath, voContent);
    
    return true;
}
```

**更新策略**:
- VO文件继承自DTO，不包含业务字段
- **无需比对，直接重新生成**
- 模板中只包含分页相关字段（pageSize、pageStart）

#### 3.4 更新Mapper.xml文件

**方法**: `updateMapperXmlFile(filePath, newClassInfo, tableConfig)`

```java
private boolean updateMapperXmlFile(String filePath, ClassInfo newClassInfo, TableConfig tableConfig) {
    // 1. 读取现有Mapper.xml
    String content = Files.readAllBytes(filePath);
    
    // 2. 解析现有字段（从resultMap中提取）
    List<FieldInfo> oldFields = parseMapperXmlFields(content);
    
    // 3. 比对字段差异
    FieldDiff diff = FieldDiffUtil.compareFields(oldFields, newClassInfo.getFieldList());
    
    if (!diff.hasChanges()) return false;
    
    // 4. 更新各个部分
    content = updateResultMap(content, diff, newClassInfo);
    content = updateBaseColumnList(content, newClassInfo);
    content = updateInsertStatement(content, diff, newClassInfo);
    content = updateUpdateStatement(content, diff, newClassInfo);
    content = updatePageListWhere(content, diff, newClassInfo);
    
    // 5. 写回文件
    Files.write(filePath, content);
    
    return true;
}
```

**更新的XML部分**:

1. **resultMap** - 字段映射关系
```xml
<resultMap id="BaseResultMap" type="...">
    <result column="graph_name"    property="graphName"    jdbcType="VARCHAR" />
    <result column="age"           property="age"          jdbcType="VARCHAR" />  <!-- 新增 -->
    <result column="status"        property="status"       jdbcType="VARCHAR" />
</resultMap>
```

2. **Base_Column_List** - 字段列表
```xml
<sql id="Base_Column_List">
    graph_name,
    age,
    status
</sql>
```

3. **insert语句** - 插入字段和if test判断
```xml
<insert id="insert">
    <trim prefix="(" suffix=")" suffixOverrides=",">
        <if test="graphName!= null and graphName !=''">
            graph_name,
        </if>
        <if test="age!= null and age !=''">
            age,
        </if>
        ...
    </trim>
    <trim prefix="values (" suffix=")" suffixOverrides=",">
        <if test="graphName!=null and graphName !=''">
            #{graphName},
        </if>
        <if test="age!=null and age !=''">
            #{age},
        </if>
        ...
    </trim>
</insert>
```

4. **update语句** - set部分和if test判断
```xml
<update id="update">
    UPDATE t_p_neb_info_auth
    <set>
        <if test="graphName!= null and graphName !=''">
            graph_name = #{graphName},
        </if>
        <if test="age!= null and age !=''">
            age = #{age},
        </if>
        ...
    </set>
    WHERE id = #{id}
</update>
```

5. **pageList查询** - where条件
```xml
<select id="pageList" resultMap="BaseResultMap">
    SELECT <include refid="Base_Column_List" />
    FROM t_p_neb_info_auth
    <where>
        <if test="graphName!= null and graphName !=''">
            and graph_name = #{graphName,jdbcType=VARCHAR}
        </if>
        <if test="age!= null and age !=''">
            and age = #{age,jdbcType=VARCHAR}
        </if>
        ...
    </where>
    order by CREATED_AT desc
</select>
```

**XML更新策略**:
- 使用正则表达式精确定位XML节点
- 完全重新生成节点内容
- 保持XML格式和对齐

## 四、核心算法

### 4.1 字段比对算法

```java
算法：compareFields(oldFields, newFields)

输入：
  - oldFields: 现有文件中的字段列表
  - newFields: 新SQL解析出的字段列表

输出：
  - FieldDiff对象，包含：
    - addedFields: 新增字段
    - removedFields: 删除字段
    - remainingFields: 保留字段

步骤：
1. 创建oldFieldMap，以fieldName为key
2. 创建newFieldMap，以fieldName为key
3. 遍历newFields：
   - 如果fieldName不在oldFieldMap中 → 新增字段
   - 否则 → 保留字段
4. 遍历oldFields：
   - 如果fieldName不在newFieldMap中 → 删除字段
5. 返回FieldDiff

时间复杂度：O(n + m)，n和m分别为新旧字段数量
```

### 4.2 DTO字段解析算法

```java
算法：parseDtoFields(content)

输入：
  - content: DTO文件内容字符串

输出：
  - List<FieldInfo>: 字段信息列表

正则表达式：
  /\*\*[\s\S]*?\*/\s*private\s+(\w+(?:<[^>]+>)?(?:\[\])?)\s+(\w+);

匹配示例：
  /**
   * 用户名
   */
  private String userName;
  
  捕获组：
  - group(1): String (字段类型)
  - group(2): userName (字段名)

步骤：
1. 使用正则表达式匹配所有字段声明
2. 对每个匹配：
   - 提取字段类型
   - 提取字段名
   - 向前查找注释（200字符内）
   - 提取注释内容
3. 创建FieldInfo对象并添加到列表
4. 返回字段列表
```

### 4.3 Mapper.xml字段解析算法

```java
算法：parseMapperXmlFields(content)

输入：
  - content: Mapper.xml文件内容

输出：
  - List<FieldInfo>: 字段信息列表

正则表达式：
  <result\s+column="([^"]+)"[^>]*property="([^"]+)"[^>]*jdbcType="([^"]+)"[^>]*/>

匹配示例：
  <result column="graph_name" property="graphName" jdbcType="VARCHAR" />
  
  捕获组：
  - group(1): graph_name (列名)
  - group(2): graphName (属性名)
  - group(3): VARCHAR (JDBC类型)

步骤：
1. 使用正则表达式匹配resultMap中的所有result标签
2. 对每个匹配：
   - 提取列名
   - 提取属性名
   - 提取JDBC类型
3. 创建FieldInfo对象并添加到列表
4. 返回字段列表
```

## 五、关键设计决策

### 5.1 为什么DTO使用重新生成而不是增量修改？

**原因**:
1. **可靠性**: 增量修改容易破坏文件结构，特别是：
   - 正则表达式匹配可能过度或不足
   - 插入位置可能不正确
   - 格式对齐难以保证

2. **简洁性**: 重新生成代码更简单清晰

3. **一致性**: 保证生成的代码格式始终符合模板规范

**代价**:
- 失去了保留手动修改的能力
- 如果开发者在DTO中添加了自定义代码，会被覆盖

**解决方案**:
- DTO应该是纯数据对象，不应包含业务逻辑
- 业务逻辑应该在Service/Manager层实现

### 5.2 为什么Mapper.xml使用增量更新？

**原因**:
1. **保留自定义SQL**: Mapper.xml中可能包含开发者自定义的查询语句

2. **只更新标准部分**: 只更新固定格式的部分（resultMap、insert、update、pageList）

3. **精确控制**: 使用正则表达式可以精确定位和替换XML节点

### 5.3 为什么跳过Controller和Manager？

**原因**:
1. **业务逻辑**: Controller和Manager包含业务逻辑，自动修改可能破坏功能

2. **API契约**: Controller的接口定义涉及到API契约，不能随意修改

3. **复杂性**: 业务逻辑的修改需要人工判断和设计

**实践**:
- 增量更新后，开发者需要手动检查并更新Controller和Manager
- 可以参考新增的DTO字段，手动添加相关业务逻辑

## 六、使用建议

### 6.1 最佳实践

1. **使用版本控制**: 在执行增量更新前提交代码，便于回滚

2. **先测试后应用**: 在测试环境验证后再应用到开发环境

3. **检查生成结果**: 更新后查看diff，确认变更符合预期

4. **更新业务逻辑**: 手动更新Controller和Manager中的相关代码

5. **运行测试**: 执行单元测试和集成测试

### 6.2 常见场景

**场景1: 新增字段**
```
修改SQL → 调用API → 系统自动：
  - DTO添加新字段
  - VO重新生成（继承新字段）
  - Mapper.xml添加字段映射和if test
→ 手动更新Controller和Manager
```

**场景2: 删除字段**
```
修改SQL → 调用API → 系统自动：
  - DTO删除旧字段
  - VO重新生成
  - Mapper.xml删除字段映射
→ 手动清理Controller和Manager中的引用
```

**场景3: 重命名字段**
```
修改SQL → 调用API → 系统识别为：
  - 删除旧字段名
  - 新增新字段名
→ 手动更新Controller和Manager中的字段引用
```

## 七、总结

`generateXmlAndIncrementalUpdate` 方法通过以下步骤实现增量更新：

1. **生成XML配置** - 从SQL文件读取表结构
2. **解析配置** - 提取表和字段信息
3. **字段比对** - 识别新增、删除的字段
4. **文件更新** - 重新生成DTO/VO，增量更新Mapper.xml
5. **结果汇总** - 返回更新统计

整个过程自动化、安全可靠，大幅提升了开发效率。
