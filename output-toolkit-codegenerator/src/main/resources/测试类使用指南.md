# JUnit4 测试类模板使用指南

## 📋 概述

`riskproduct_test.ftl` 是一个功能完整的 JUnit4 测试类模板，集成了 Spring Boot Test、Mockito 等常用测试框架，并内置了大量测试技巧和最佳实践。

## 🚀 快速开始

### 1. 生成测试类

使用代码生成器选择 `riskproduct_test` 模板即可生成完整的测试类。

### 2. 配置测试环境

#### 方式一：使用独立的测试配置文件

在 `src/test/resources` 目录下创建 `application-test.yml`：

```yaml
# 忽略 Zookeeper
dubbo:
  registry:
    address: N/A
  # 或者
  zk:
    url: none

# 忽略 Redis（使用本地或不启动）
spring:
  redis:
    host: 127.0.0.1
    port: 6379

# 使用内存数据库 H2（无需安装数据库）
spring:
  datasource:
    driver-class-name: org.h2.Driver
    url: jdbc:h2:mem:testdb
    username: sa
    password: 

# 禁用定时任务
spring:
  task:
    scheduling:
      enabled: false

# 禁用消息队列自动启动
spring:
  rabbitmq:
    listener:
      simple:
        auto-startup: false
```

#### 方式二：使用注解覆盖配置

在测试类上添加 `@TestPropertySource` 注解：

```java
@TestPropertySource(properties = {
    "dubbo.registry.address=N/A",
    "spring.redis.host=127.0.0.1"
})
public class SomeControllerTest {
    // ...
}
```

## 🎯 核心功能

### 1. Mock 支持

#### 基本用法

```java
@MockBean
private SomeExternalService someExternalService;

@Before
public void setUp() {
    // 模拟方法返回值
    when(someExternalService.getData()).thenReturn("mock data");
}
```

#### 常用 Mock 场景

```java
// 1. 模拟返回固定值
when(service.method(anyString())).thenReturn("result");

// 2. 模拟抛出异常
when(service.method()).thenThrow(new RuntimeException("测试异常"));

// 3. 模拟不同参数返回不同结果
when(service.method("param1")).thenReturn("result1");
when(service.method("param2")).thenReturn("result2");

// 4. 模拟 void 方法
doNothing().when(service).voidMethod(any());

// 5. 模拟多次调用返回不同结果
when(service.method())
    .thenReturn("first")
    .thenReturn("second")
    .thenReturn("third");
```

### 2. 验证方法调用

```java
// 验证方法被调用
verify(service).method(any());

// 验证方法被调用指定次数
verify(service, times(1)).method(any());
verify(service, times(2)).method(any());

// 验证方法从未被调用
verify(service, never()).method(any());

// 验证方法至少被调用N次
verify(service, atLeast(1)).method(any());

// 验证方法最多被调用N次
verify(service, atMost(3)).method(any());
```

### 3. 断言验证

```java
// 基本断言
assertNotNull("对象不能为空", object);
assertNull("对象应该为空", object);
assertTrue("条件应该为真", condition);
assertFalse("条件应该为假", condition);

// 相等性断言
assertEquals("期望值", actual);
assertEquals(100, result.intValue());
assertNotEquals("不应该相等", actual);

// 引用断言
assertSame(expected, actual); // 同一个对象引用
assertNotSame(expected, actual); // 不是同一个对象引用

// 数组断言
assertArrayEquals(expectedArray, actualArray);

// 集合断言（需要 hamcrest）
assertThat(list, hasSize(3));
assertThat(list, contains("a", "b", "c"));
assertThat(map, hasKey("key"));
```

### 4. 事务回滚

测试完成后自动回滚数据，避免污染数据库：

```java
@Transactional
@Rollback(true)
public class SomeControllerTest {
    // 测试方法执行完会自动回滚
}
```

### 5. 执行 SQL 脚本

在测试前执行 SQL 脚本初始化数据：

```java
@Sql(scripts = "/test-data.sql", executionPhase = Sql.ExecutionPhase.BEFORE_TEST_METHOD)
@Sql(scripts = "/clean-data.sql", executionPhase = Sql.ExecutionPhase.AFTER_TEST_METHOD)
@Test
public void testMethod() {
    // 测试逻辑
}
```

## 📝 测试技巧

### 1. 异常测试

```java
// 方式一：使用 expected 属性
@Test(expected = IllegalArgumentException.class)
public void testException() {
    service.methodThrowException();
}

// 方式二：使用 try-catch
@Test
public void testException() {
    try {
        service.methodThrowException();
        fail("应该抛出异常");
    } catch (IllegalArgumentException e) {
        assertEquals("预期的异常消息", e.getMessage());
    }
}
```

### 2. 超时测试

```java
@Test(timeout = 1000) // 限制执行时间不超过 1000 毫秒
public void testTimeout() {
    // 测试逻辑
}
```

### 3. 忽略测试

```java
@Ignore("暂时忽略这个测试")
@Test
public void testTempIgnore() {
    // 测试逻辑
}
```

### 4. 参数化测试

```java
@RunWith(Parameterized.class)
public class ParameterizedTest {
    
    @Parameterized.Parameters
    public static Collection<Object[]> data() {
        return Arrays.asList(new Object[][] {
            { 1, "one" },
            { 2, "two" },
            { 3, "three" }
        });
    }
    
    private int input;
    private String expected;
    
    public ParameterizedTest(int input, String expected) {
        this.input = input;
        this.expected = expected;
    }
    
    @Test
    public void test() {
        assertEquals(expected, service.convert(input));
    }
}
```

### 5. 只加载特定层的测试

```java
// 只测试 Web 层
@WebMvcTest(SomeController.class)
public class SomeControllerTest {
    @Autowired
    private MockMvc mockMvc;
}

// 只测试 JPA 层
@DataJpaTest
public class SomeRepositoryTest {
    @Autowired
    private TestEntityManager entityManager;
}

// 只测试 JSON 序列化
@JsonTest
public class JsonTest {
    @Autowired
    private JacksonTester<MyObject> json;
}
```

## 🔧 常见问题

### Q1: 测试时如何跳过 Dubbo 注册中心？

**A:** 在配置文件中设置：
```yaml
dubbo:
  registry:
    address: N/A
```
或使用注解：
```java
@TestPropertySource(properties = {"dubbo.registry.address=N/A"})
```

### Q2: 测试时如何使用内存数据库？

**A:** 添加 H2 依赖并配置：
```xml
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>test</scope>
</dependency>
```

```yaml
spring:
  datasource:
    url: jdbc:h2:mem:testdb
    driver-class-name: org.h2.Driver
```

### Q3: 如何避免测试数据污染数据库？

**A:** 使用 `@Transactional` 和 `@Rollback(true)` 注解，测试完成后自动回滚。

### Q4: Mock 的对象不生效怎么办？

**A:** 检查以下几点：
1. 确认使用的是 `@MockBean` 而不是 `@Mock`
2. 确认 Mock 的设置在测试方法调用之前
3. 确认参数匹配器使用正确（如 `any()`, `anyString()` 等）

### Q5: 如何调试测试代码？

**A:** 
1. 使用 `log.info()` 打印关键信息
2. 在测试方法中设置断点，以 Debug 模式运行
3. 使用 `System.out.println()` 输出中间结果

## 📚 最佳实践

1. **测试命名规范**：`test + 方法名 + 场景描述`
   - 示例：`testInsert_WithValidData()`
   - 示例：`testUpdate_WithNonExistentId()`

2. **遵循 AAA 模式**：
   - Arrange（准备）：准备测试数据
   - Act（执行）：调用被测试的方法
   - Assert（断言）：验证结果

3. **保持测试独立性**：每个测试方法应该独立运行，不依赖其他测试

4. **测试边界条件**：不仅测试正常情况，还要测试边界值和异常情况

5. **使用有意义的断言消息**：便于快速定位问题

6. **及时清理测试数据**：使用 `@After` 或事务回滚

7. **合理使用 Mock**：只 Mock 外部依赖，不 Mock 被测试的对象
